$ rc --help
rootcause CLI — a thin, scriptable client over the rootcause API

Usage:
  rc [command]

Start:
  status      Health summary + recent runs
  ask         Trigger a run from a question and wait for the answer
  run         Inspect and manage the run lifecycle

Manage:
  project     Manage project configuration and resources

Develop:
  dev         Develop and inspect project behavior

Operate:
  fleet       Operate and inspect project health
  admin       Box-level administration (users/projects/catalog; global-admin token)

Local:
  auth        Manage local authentication and inspect access
  self        Manage the rc installation and shell integration

Flags:
      --no-preview       write large output artifacts but omit head/tail previews
      --out-dir string   directory for large output artifacts (default: RC_OUTPUT_DIR or .rootcause/output)
  -o, --output string    output format: json|table (default: auto-detect)
      --profile string   token profile to use (default: auto — the brain in the current directory, else "default")
      --project string   scope the request to one project by name or id (default: RC_PROJECT; requires an all-projects token)
      --raw-output       disable progressive output spill and print full payloads to stdout
      --scope string     force request routing: project|tenant. "project" clears any resolved tenant (--tenant, a brain checkout, or a tenant-bound login) so a tenant-capable command hits the project route; "tenant" requires a resolvable tenant. With a tenant-pinned token, --scope project routes to the project and the server returns 403 — the flag controls routing, not authorization.
      --tenant string    override the login tenant where supported (default: RC_TENANT)

Use "rc [command] --help" for more information about a command.

$ rc ask --help
Trigger a run from a question and wait for the answer

Usage:

Flags:
      --asserted-by string      who asserted the principal (default server-side); requires the --principal-kind/--principal-id pair

$ rc project mailbox seed-imap --help
Save everything about a generic IMAP/SMTP mailbox except the password, then print a stable, no-login link to send to whoever holds that password.

Nothing is probed yet — there is no credential to authenticate with. The mailbox sits in awaiting_credential (never polled, so it cannot fail in the background) until someone opens the link and enters the password; it goes live automatically when that password passes the live check.

$ rc project database --help
Manage registered databases (list/read/update + access controls).

There is no "database add": a database EXISTS because a sealed grounding env key named
<PROJECT>_<DBKEY>_DSN exists. To register one (read-only DB role; the rootcause box must be
network-allowlisted by your DB provider):

  printf %s "$DSN" | rc project env set key=<PROJECT>_<DBKEY>_DSN

<dbkey> lowercased is the db= short name brain scripts use: PROBACKUP_BACKUPS_DSN <-> lib.db(db="backups").
Verify the DSN env actually resolves with `rc dev console database list`.

`ls` here lists the DSNs this project has CONFIGURED (description, scope manifest, or PII columns) —
a brand-new DSN shows up once you annotate it: `rc project database set <PROJECT>_<DBKEY>_DSN description=…`.

`*_WRITE_DSN` keys are the action/write plane (--plane action), not grounding databases.
